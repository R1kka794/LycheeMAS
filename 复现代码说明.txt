开发目标
========
复现重点是“自动生成 rubrics，并改编为 MAS 步骤级奖励”：
- 将一次智能体发言或工具调用定义为一步；
- 根据任务目标、当前角色、此前交互历史，为每步生成评分细则；
- 由评审模型对实际输出逐条给出“满足/不满足”及理由；
- 按权重归一化，得到该步奖励值；
- 输出“步骤—智能体—评分细则—奖励值—评分依据”结果表；
- 完成细则生成与奖励计算，不做 GRPO 训练。

新增/修改文件

1. src/lychee_mas/methods/postrun/rubric_step_reward.py
------------------------------------------------------
新增 postrun 读侧可跑实现，包含：

（1）注册 attributor/rubric_step_reward
类名：RubricStepRewardAttributor
功能：
- 遍历 Trajectory.messages，把每条 Message 当作一步；
- 自动识别 action_type：普通发言 utterance 或工具调用 tool_call；
- 从 task_goal 参数、context 或 trajectory.meta 中读取任务目标；
- 为每步生成 rubrics：
  - 如果传入 rubric_llm，则调用模型生成 JSON rubrics；
  - 如果不传 rubric_llm，则使用内置四类通用 rubrics：
    1) 当前子任务完成度；
    2) 是否正确使用已有信息；
    3) 是否提供必要依据/合理工具使用；
    4) 是否符合角色与格式约束。
- 调用 judge_llm 评审每条 rubric 是否满足，并解析 JSON 输出；
- 按权重归一化计算 step_reward ∈ [0, 1]；
- 生成每步 Attribution，并把完整结果写入 trajectory.meta["rubric_step_reward"]。

trajectory.meta["rubric_step_reward"] 的主要字段：
- task_goal：任务目标；
- steps：每一步的 agent、role、action_type、output、reward、rubrics、judgements；
- criteria_rows：结果表，每行包含：
  step / agent / role / action_type / criterion_id / 评分细则 / weight /
  satisfied / reward_value / step_reward / 评分依据；
- agent_rewards：按 agent 聚合后的平均步骤奖励。

（2）注册 credit_assigner/step_reward
类名：StepRewardCreditAssigner
功能：
- 从 RubricStepRewardAttributor 产出的 Attribution.meta["step_reward"] 中读取步骤奖励；
- 按 agent 聚合为信用分数；
- 支持 aggregation="mean" 或 "sum"；
- 可选 use_external_reward=True，把外部传入的 score/reward 作为缩放因子。

（3）辅助数据结构与工具函数
- StepRubric：单条评分细则；
- RubricJudgement：评审模型对单条细则的判断；
- StepRewardRecord：一步的奖励汇总；
- JSON 解析、模型回调调用、rubric/judgement 校验、启发式评审等纯标准库工具函数。

典型用法
========

from lychee_mas.plugins.postrun import analyze_run

credits = analyze_run(
    traj,
    method="rubric_step_reward",
    credit_assigner="step_reward",
    task_goal="完成任务并给出必要依据",
    judge_llm=my_llm,       # sync(prompt)->str 或 async(prompt)->str
    rubric_llm=None,        # None 时使用内置通用 rubrics；也可注入模型自动生成
)

table = traj.meta["rubric_step_reward"]["criteria_rows"]

评审模型 judge_llm 输出格式
==========================
judge_llm 需要返回 JSON，例如：

{
  "judgements": [
    {"criterion_id": "subtask_completion", "satisfied": true, "reason": "本步给出了明确中间结论。"},
    {"criterion_id": "use_existing_information", "satisfied": false, "reason": "未引用上一位 agent 的关键结果。"}
  ]
}

如果启用 rubric_llm，其输出格式为：

{
  "rubrics": [
    {"id": "c1", "description": "是否完成当前子任务", "weight": 0.4, "rationale": "..."}
  ]
}

显式错误策略
============
- 没有 judge_llm 且 heuristic_judge=False 时会报错，避免静默伪评审；
- 缺少任务目标会报错；
- 空轨迹会报错；
- 模型返回非 JSON、字段缺失、评审条数与 rubric 条数不一致都会显式报错。
